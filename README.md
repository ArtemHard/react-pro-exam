# React PRO — финальный проект

## Что было сделано

- переработана структура проекта: код разделён на слои `app`, `pages`, `widgets`, `features` и `shared`;
- переиспользуемые UI-компоненты вынесены в `src/shared/ui`: `Button`, `Input`, `Loader`, `Modal`, `Rating`, `Logo`, `ButtonBack`;
- бизнес-функциональность разделена по фичам: `auth`, `cart`, `products`, `search`;
- добавлено универсальное модальное окно через `ReactDOM.createPortal` с закрытием по `Escape`, клику по overlay и управлением фокусом;
- реализован `useOptimistic` для лайков: интерфейс обновляется сразу, при ошибке состояние откатывается;
- выполнена оптимизация рендеров: `React.memo`, `useMemo`, `useCallback`, точечные селекторы и оптимистичное обновление кэша RTK Query;
- добавлена альтернативная production-сборка на Vite + SWC и выполнено её сравнение с Webpack;
- React и ReactDOM обновлены до версии 19.3.1.

## Сравнение сборок

В проекте осталась штатная Webpack-сборка и добавлена альтернативная production-сборка на **Vite + SWC**.

Команды:

```bash
npm run build        # Webpack -> dist
npm run build:vite   # Vite + SWC -> dist-vite
npm run dev:vite     # dev-сервер Vite
npm run preview:vite # предпросмотр production-сборки Vite
```

### Результаты замеров

| Сборщик | Build time (среднее) | Размер build (raw) | Размер build (gzip) |
|---|---:|---:|---:|
| Webpack 5.93.0 + ts-loader | 34.33 сек | 0.77 MB | 0.24 MB |
| Vite 7.3.7 + SWC | 9.97 сек | 0.76 MB | 0.24 MB |

Детализация по файлам:

| Сборщик | JS | CSS | Прочее |
|---|---:|---:|---:|
| Webpack | 0.71 MB | 0.06 MB | <0.01 MB (HTML + LICENSE) |
| Vite | 0.69 MB | 0.05 MB | 0.01 MB (HTML + 2 SVG) |

Выводы:

- Vite + SWC собирает проект примерно в **3,4 раза быстрее** Webpack (9.97 сек против 34.33 сек).
- Итоговый размер сборки Vite немного меньше: **0.76 MB против 0.77 MB** (около 1,5%).
- В gzip-размере разница практически отсутствует: 0.24 MB в обоих случаях.
- Vite таргетирует `es2015` и выносит часть SVG в отдельные файлы, Webpack собирает код под ES5 и встраивает SVG в JS — это влияет на структуру и размер бандла.

## Оптимизация

Лишние рендеры искались через React DevTools Profiler. Основные hotspots — шапка сайта и список карточек товаров: они перерисовывались при изменении корзины и кэша товаров, хотя их собственные данные не менялись.

Что изменено:

- `Card` и `LikeButton` обёрнуты в `React.memo` — перерисовывается только карточка, у которой изменились данные;
- `CardList` подписывается на корзину один раз и передаёт в `Card` готовый флаг `isProductInCart`, поэтому изменение корзины не затрагивает весь список;
- `Set` с идентификаторами товаров в корзине вычисляется через `useMemo`;
- `fetchMoreProducts` в `useLoadMore` стабилизирован через `useCallback`;
- итоги корзины (`allPrice`, `allDiscount`) в `CartAmount` вычисляются через `useMemo`, а не при каждом рендере;
- список избранных товаров в `useProducts` фильтруется через `useMemo`;
- обработчики в `useCount` и `addProductToCart` в `useAddToCart` стабилизированы через `useCallback`;
- `CartItem` обёрнут в `React.memo`, поэтому при изменении количества одного товара остальные элементы списка корзины не перерисовываются;
- `useCount` выбирает только `count` и `stock` нужного товара, а не весь массив корзины;
- `setCartProductCount` изменяет только нужный товар, не пересоздавая объекты остальных;
- из `Header` вынесены независимые `FavoritesBadge` и `CartBadge`, поэтому сама шапка не перерисовывается при изменении корзины или лайков;
- у мутаций лайков убрана инвалидация тега `Products/list`, вместо неё используется оптимистичное обновление кэша.

Результат: при добавлении товара в корзину, изменении количества и лайке перерисовывается только изменённый компонент, а не весь список товаров, не остальные элементы корзины и не шапка сайта.
